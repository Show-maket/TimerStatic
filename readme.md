# TimerStatic Library

Лёгкая и эффективная библиотека таймеров для Arduino, которая предоставляет статическую функциональность таймеров с поддержкой различных типов обратных вызовов.

## Возможности

- **Статическое управление таймерами**: Эффективное управление таймерами на основе связанного списка
- **Множественные типы обратных вызовов**: Поддержка указателей на функции, лямбда-функций и объектно-ориентированных обратных вызовов
- **Управление жизненным циклом**: Счётчики и временные ограничения жизненного цикла таймеров
- **Функциональность задержки**: Встроенные возможности задержки и таймаута
- **Эффективность памяти**: Минимальное потребление памяти с умным управлением ресурсами
- **Кросс-платформенность**: Совместимость с платами AVR и не-AVR Arduino
- **Контейнеры и пулы**: `Timer` нельзя копировать, но `noexcept`-перемещение переносит его узел без изменения порядка планировщика

## Установка

1. Скачайте библиотеку
2. Распакуйте в папку библиотек Arduino
3. Перезапустите Arduino IDE
4. Подключите библиотеку: `#include "TimerStatic.h"`

## Базовое использование

```cpp
#include "TimerStatic.h"

// Создаём таймер, который срабатывает каждые 1000мс
Timer timer(1000, millis, []() {
  digitalWrite(LED_BUILTIN, !digitalRead(LED_BUILTIN));
});

void setup() {
  pinMode(LED_BUILTIN, OUTPUT);
}

void loop() {
  timer.check();  // Проверяем, должен ли сработать таймер
}
```

## Типы таймеров

### Периодический таймер
```cpp
// Таймер, который работает бесконечно
Timer timer(1000, millis, callbackFunction);
```

### Таймер с ограничением по количеству
```cpp
// Таймер, который работает определённое количество раз
timer.forCount(1000, millis, callbackFunction, 5);
```

### Таймер с временным ограничением
```cpp
// Таймер, который работает определённое время
timer.forTime(1000, millis, callbackFunction, 10000); // 10 секунд
```

### Таймер задержки
```cpp
// Таймер однократной задержки
timer.delay(5000, millis, callbackFunction); // 5 секунд задержки
```

## Типы обратных вызовов

### Указатель на функцию
```cpp
void myCallback() {
  // Ваш код здесь
}
Timer timer(1000, millis, myCallback);
```

### Лямбда-функция (платы не-AVR)
```cpp
Timer timer(1000, millis, []() {
  // Ваш код здесь
});
```

### Объектно-ориентированный обратный вызов
```cpp
class MyClass {
public:
  void callback() {
    // Ваш код здесь
  }
};

MyClass obj;
Timer timer(1000, millis, [](void* obj) {
  static_cast<MyClass*>(obj)->callback();
}, &obj);
```

## Справочник API

### Конструктор
```cpp
Timer(unsigned long time, TimeFunc t_func, CallbackFunc callback, bool isPre = false);
Timer(unsigned long time, TimeFunc t_func, CallbackFuncParam callbackP, bool isPre = false);
Timer(unsigned long time, TimeFunc t_func, std::function<void()> callbackStd, bool isPre = false);
```

Объект `Timer` не копируется, но поддерживает move-конструктор и move-assignment.
Перемещение сохраняет логическую позицию исходного таймера в intrusive-списке, а
перемещённый-from объект остаётся пустым и несвязанным. Это позволяет использовать
`Timer` в контейнерах и повторно занимать ячейки пула.

`Timer` переносит `obj` и callback без изменения их содержимого. Если `obj` указывает
на адрес внешнего владельца или lambda захватила `this` владельца, move-реализация
этого владельца должна самостоятельно перепривязать такие ссылки. Создание сразу
на окончательном месте (`emplace`) всё равно предпочтительнее лишнего перемещения.

Для совместимости конструктор сохраняет историческую семантику первого запуска:
при `isPre == false` первый callback уже готов к вызову ближайшим `check()`/`tick()`.
Методы `set*()` при `isPre == false`, напротив, назначают первый вызов через один период.

### Методы
- `void check()` - Проверить, должен ли сработать таймер
- `bool resume()` - Продолжить только полностью валидно настроенный таймер; возвращает успех
- `bool restart()` - Проверить конфигурацию, включить и назначить следующий вызов через период
- `void ON()` - Совместимая обёртка над `resume()`; не создаёт работающий «зомби»-таймер
- `void OFF()` - Выключить таймер
- `bool isRun()` - Проверить, работает ли таймер
- `void setPeriod(uint32_t val)` - Изменить период без переноса уже назначенного ближайшего deadline
- `void restartWithPeriod(uint32_t val)` - Изменить период и перенести ближайший deadline на `now + val`; сам по себе не включает выключенный таймер
- `uint32_t getPeriod()` - Получить период таймера

### Статические методы
- `static void tick()` - Обработать все таймеры (альтернатива индивидуальным вызовам check)

`tick()` допускает удаление из callback текущего таймера, следующего таймера и любого
другого таймера списка. Объекты, созданные во время текущего прохода, впервые
рассматриваются только следующим `tick()`. Вложенный `tick()` игнорируется.

Диагностический observer обхода отсутствует в обычной сборке. Для целевой отладки
его можно добавить глобальным compiler flag
`-DTIMER_STATIC_ENABLE_OBSERVER=1`; значение по умолчанию — `0`.

Нулевой период разрешён только для однократного `delay(0, ...)`. Периодические
конструкторы, `set*()`, `forCount*()` и `forTime*()` с периодом `0` остаются
остановленными; после исправления периода их можно явно запустить через `resume()`.
